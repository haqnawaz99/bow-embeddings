## What this notebook covers

Every weakness listed in NB08's "What This Is NOT" section becomes a lesson here. Seven upgrades are applied to the naive RAG baseline, each measured against the previous approach: hybrid retrieval, cross-encoder re-ranking, HyDE query expansion, sentence-boundary chunking, contextual compression, RAGAS-style evaluation, and a full pipeline comparison.

## What the previous approach got wrong

NB08 used dense-only retrieval, no re-ranking, plain queries, full verses as retrieval units, full context passed to the LLM, and no evaluation metrics. Each of these is a known production failure mode.

## Key concept

The full advanced RAG pipeline:

```
Query
  |
  +-----------> [BM25 sparse index]  \
  |                                   > RRF fusion --> hybrid top-20
  +-----------> [SBERT dense index]  /
                        |
                        v
           [Cross-encoder re-ranker]   --> top-4
                        |
                        v
           [Contextual compression]    --> strip irrelevant sentences
                        |
                        v
              [Prompt builder]         --> grounded prompt
                        |
                        v
            [flan-t5-small LLM]        --> answer
                        |
                        v
         [RAGAS-style evaluation]      --> faithfulness + relevance scores
```

## Topics covered

**Section 2 — Hybrid Retrieval (BM25 + SBERT + RRF)**

- `BM25Okapi` for sparse keyword recall
- `IndexFlatIP` for dense semantic recall
- Reciprocal Rank Fusion (RRF): `score = 1 / (k + rank)`, k=60
- Dense-only vs hybrid overlap comparison

**Section 3 — Cross-Encoder Re-ranking**

- `CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")`
- Bi-encoder vs cross-encoder: independent vs joint encoding
- Rank shift analysis: RRF rank → CE rank

**Section 4 — HyDE Query Expansion**

- Generate a hypothetical answer to the query with flan-t5-small
- Embed the hypothetical answer instead of the raw query
- Dense-only vs HyDE result comparison with scores

**Section 5 — Sentence-Boundary Chunking**

- Split verses into overlapping sentence windows
- `CHUNK_SIZE=3`, `CHUNK_OVERLAP=1`
- Verse-level vs chunk-level retrieval side by side

**Section 6 — Contextual Compression**

- Score each sentence in a passage against the query with the cross-encoder
- Keep only the top N sentences per passage
- Before/after compression with CE scores per sentence

**Section 7 — RAGAS-style Evaluation**

- Faithfulness: max CE score of each answer sentence against context passages
- Answer relevance: CE score of (query, answer) pair
- Note: CE scores are raw logits — relative ordering matters, not absolute values

**Section 8 — Full Pipeline Comparison**

- Naive (dense-only) vs Advanced (hybrid + re-rank) on 3 test queries
- Faithfulness and relevance scores side by side

## Reflection questions

1. RRF uses `k=60`. What happens at `k=1`? What about `k=1000`?
2. Why can the cross-encoder model richer query-document interactions than the bi-encoder?
3. Describe two scenarios where HyDE would perform *worse* than vanilla dense retrieval.
4. Contextual compression can remove too aggressively. What goes wrong when the kept sentences lose their referential context?
5. We use the cross-encoder for both re-ranking and evaluation. What are the risks of using the same model for both tasks?
